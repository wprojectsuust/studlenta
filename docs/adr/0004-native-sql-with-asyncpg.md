# ADR-0004: Нативный SQL на asyncpg без ORM

- **Статус:** принято
- **Дата:** 2026-10-23

## Контекст
Требование: async и нативный SQL. Ключевые запросы — лента с подсчётом лайков, флагами
текущего пользователя, полнотекстовым поиском и keyset-пагинацией; календарь с группировкой
по дням в часовом поясе.

## Решение
asyncpg напрямую. SQL живёт в `infrastructure/db/` рядом с маппингом строк в DTO/сущности.
Значения — только параметрами `$1..$N`; в строку запроса склеиваются лишь константы модуля
(правило S608 отключено для этой папки с пояснением в `pyproject.toml`).

Запись — через доменные сущности (`EventRepository`), чтение для экранов — отдельные запросы,
сразу собирающие DTO (`EventQueries`).

## Рассмотренные варианты
- **SQLAlchemy 2.0 async** — сильный инструмент, но запросы ленты всё равно пришлось бы
  писать на `text()`, а маппинг сущностей добавляет слой без пользы для такой схемы.

## Последствия
- Каждый запрос виден целиком и проверяется интеграционным тестом на настоящем PostgreSQL.
- Нет N+1: лента — один запрос.
- Маппинг строк пишется руками — это ~100 строк, их покрывают тесты round-trip.
