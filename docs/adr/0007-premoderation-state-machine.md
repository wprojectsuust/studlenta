# ADR-0007: Предмодерация как машина статусов с оптимистической блокировкой

- **Статус:** принято
- **Дата:** 2026-10-23

## Контекст
Главное требование задачи — обязательная предмодерация. Из дизайна: модератор может
одобрить, вернуть на доработку с комментарием или отклонить с причиной; автор видит статус
и комментарий; модераторов несколько.

## Решение
Статусы `draft → pending → published | changes_requested | rejected`, `published → archived`.
Переходы — методы `Event`, недопустимый переход — `InvalidTransitionError` (HTTP 409).
Комментарий обязателен при возврате и отклонении. Модератор не модерирует своё событие.
Каждое решение пишется в `moderation_log` и создаёт уведомление автору **в одной транзакции**.

Гонку двух модераторов ловит `version`: `UPDATE … WHERE id = $1 AND version = $2`,
0 строк → `ConflictError` (HTTP 409).

## Последствия
- Публичные запросы фильтруют только `status = 'published'`.
- Повторная отправка после возврата видна модератору как «исправлено автором».
- Удалить можно только черновик; отправленное — только в архив, история сохраняется.
