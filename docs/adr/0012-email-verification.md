# ADR-0012: Подтверждение почты при регистрации через собственный postfix

- **Статус:** принято
- **Дата:** 2026-10-23

## Контекст
Регистрироваться может кто угодно, а событие после одобрения видит весь университет.
Нужно хотя бы убедиться, что у автора есть доступ к указанной почте. На VPS уже работает
postfix + dovecot + opendkim для домена karrad.tech (SPF, DKIM, DMARC настроены), но домен
и IP молодые — письма могут попадать в «Спам».

## Решение
- Отдельный ящик `studlenta@karrad.tech`; API отправляет через submission (587, STARTTLS,
  логин и пароль). DKIM подписывает сам opendkim (`*@karrad.tech`).
- После регистрации — письмо со ссылкой `…/studlenta/verify-email?token=…`. Токен —
  256 бит, в базе только SHA-256, живёт сутки. Повторное письмо — не чаще раза в минуту.
- **Без подтверждения можно входить, лайкать, вести черновики, но нельзя отправить событие
  на модерацию.** Блокировать вход не стали: из-за «Спама» это отрезало бы часть студентов.
- Письмо уходит фоновой задачей после ответа; сбой SMTP не ломает регистрацию — пользователь
  запросит письмо ещё раз из баннера.
- Аккаунты из CLI (модераторы) и все, что существовали до миграции, считаются подтверждёнными.
- Отправитель выбирается окружением: SMTP (прод), JSON-файлы в папке (e2e — тест читает
  ссылку из «письма»), журнал (разработка без почты).

## Рассмотренные варианты
- **Внешний сервис (Mailgun, SendGrid, Unisender)** — лучше доставляемость, но регистрация,
  ключи и лимиты; для хакатона свой postfix достаточен.
- **Код из письма вместо ссылки** — лишний ввод на телефоне.

## Последствия
- Чтобы реже попадать в «Спам»: PTR-запись IP → mail.karrad.tech у хостера, отправка
  только с этого ящика, текст без «рекламных» слов.
- Пароль ящика — только в `/opt/studlenta/.env` на сервере.
