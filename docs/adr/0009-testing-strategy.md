# ADR-0009: Три уровня тестов и TDD

- **Статус:** принято
- **Дата:** 2026-10-23

## Контекст
Требования: unit, integration и e2e-тесты; разработка через TDD.

## Решение
| Уровень | Что | Инструмент | Скорость |
|---------|-----|-----------|----------|
| unit | домен; use case'ы на in-memory фейках; адаптеры (JWT, argon2, Pillow) | pytest | ~1 с |
| integration | SQL-репозитории и запросы на настоящем PostgreSQL 16 | testcontainers (локально) / service-контейнер (CI) | ~5 с |
| e2e | сценарии из дизайна через HTTP: регистрация → модерация → лента | httpx ASGI + настоящая база | ~6 с |

Цикл — red → green → refactor; тест пишется первым (CONTRIBUTING). Порог покрытия 90 %
проверяет CI. Фронтенд-e2e (Playwright + axe для WCAG) — вместе с фронтендом.

## Последствия
- Интеграционные и e2e-тесты требуют Docker или `TEST_DATABASE_URL`.
- Логику SQL не дублируем в фейках: `StubQueries` только запоминает аргументы.
