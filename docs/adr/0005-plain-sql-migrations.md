# ADR-0005: Миграции — пронумерованные SQL-файлы и свой раннер

- **Статус:** принято
- **Дата:** 2026-10-23

## Контекст
Без ORM автогенерация миграций не нужна. Нужен простой и предсказуемый способ катить схему
при каждом деплое.

## Решение
Файлы `infrastructure/db/migrations/NNNN_name.sql`, раннер `migrate.py` (~50 строк):
применяет недостающие по порядку, каждую в транзакции, записывает в `schema_migrations`.
`pg_advisory_lock` защищает от двух параллельных запусков. Контейнер API запускает миграции
при старте.

## Рассмотренные варианты
- **Alembic** — тянет SQLAlchemy ради одного раннера.
- **yoyo / dbmate** — внешний инструмент и ещё один формат для команды.

## Последствия
- Применённые миграции никогда не редактируются — только новый файл (CONTRIBUTING).
- Отката (down) нет: для хакатона откатываемся новой миграцией или восстановлением бэкапа.
