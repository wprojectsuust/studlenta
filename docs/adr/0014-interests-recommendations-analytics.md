# ADR-0014: Сигналы интереса, рекомендации «Для вас» и аналитика

- **Статус:** принято
- **Дата:** 2026-10-24

## Контекст
Лента с фильтрами отвечает на вопрос «что будет», но не «что интересно мне». Организаторам
и модераторам не видно, какие события и темы цепляют студентов. Хочется персональной
подборки и аналитики, не утяжеляя сервер (1 ГБ, общий с другим продом) и не собирая
персональные данные гостей.

## Решение
1. **Сигналы.** Просмотр страницы события (`POST /events/{id}/view`), лайк, избранное.
   Просмотры — таблица `event_views`: один на зрителя в день (PK `event_id, viewer,
   viewed_on`), так обновления страницы не накручивают счётчик. Зритель — `u:<id аккаунта>`
   или `g:<случайный UUID браузера>` из localStorage; ни IP, ни User-Agent не храним.
   Формат ключа проверяет CHECK в базе.
2. **Рекомендации — небольшой гибрид без ML-библиотек** (`domain/recommendations.py`,
   чистая функция, покрыта юнит-тестами):
   - интерес к категории — веса просмотр 1 / лайк 3 / избранное 5 с затуханием
     (полураспад 14 дней);
   - похожесть текста — косинус TF-IDF по лексемам заголовка и анонса; лексемы даёт
     PostgreSQL (`tsvector_to_array` поверх уже существующего `russian` tsvector), так что
     стемминг и стоп-слова — бесплатно;
   - «смотрят вместе» — item-to-item по совместным просмотрам других зрителей;
   - популярность за 14 дней — холодный старт и слабая добавка.
   Итог `0.4·категория + 0.3·похожесть + 0.2·вместе + 0.1·популярность`. Самая весомая
   часть становится **объяснением** под карточкой: «Вы часто смотрите «Концерты»»,
   «Похоже на «…»», «Смотрели те, кто смотрел «…»», «Популярно у студентов».
   Уже просмотренное не предлагается. Кандидаты — 200 ближайших опубликованных событий,
   история — 180 дней; всё считается за 3 SQL-запроса и миллисекунды Python.
3. **Гость → аккаунт.** Вошедший передаёт и id браузера: история гостя и аккаунта
   объединяется, подборка не «обнуляется» после входа.
4. **Аналитика** (`GET /analytics/interests?days=`): итоги, просмотры по дням (с пустыми
   днями), интерес по категориям, топ-10 событий с конверсией в избранное. Модератор видит
   всю ленту, автор — только свои события; гостю — 401.
5. **Кеш.** Подборка персональная — `private, no-store`, в `TtlCache` не попадает.
6. **Фронтенд.** Полоса «Для вас» под «Ближайшими» на главной; на холодном старте без
   популярного она скрыта, чтобы не дублировать «Ближайшие». Экран «Аналитика»: плитки,
   столбики по дням (одна серия, цвет акцента скина, подсказка при наведении + таблица для
   скринридеров), полосы по категориям, таблица топа.

## Рассмотренные варианты
- **Матричная факторизация / implicit ALS, scikit-learn** — сотни МБ зависимостей и
  офлайн-обучение ради сотен событий и тысяч студентов; объяснения теряются.
- **pgvector + эмбеддинги** — нужна модель и её хостинг; для коротких русских анонсов
  TF-IDF по лексемам Postgres даёт сопоставимый результат.
- **Внешняя аналитика (Метрика, GA)** — данные студентов уходят третьей стороне,
  а связать просмотры с избранным и категориями всё равно пришлось бы самим.

## Последствия
- `event_views` растёт на ~(зрители × события) в день; при росте — партиционирование по
  месяцу или чистка старше 180 дней (за окно истории не выходим).
- Просмотр можно «накрутить», меняя id браузера; для рекомендаций и внутренней аналитики
  это приемлемо, для рейтингов с призами — нет.
- Веса подобраны вручную; следующий шаг — офлайн-оценка по истории (hit rate@10).
